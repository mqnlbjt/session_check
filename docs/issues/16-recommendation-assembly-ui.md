# Issue #16: 推荐物组装 + 改进清单 UI

> Parent: 期6 改进清单（grill Q7：skills/hooks/MCP 三家全覆盖；Q8：LLM 层手动触发 + 具体化弱提示；Q11：改进清单卡片形态）

## What to build

- **弱提示**：Harness 页显示「{项目名} 有 N 条已确认信号待诊断」+「生成建议」按钮——够具体，不只是小红点
- **生成建议**（手动触发，后台异步 + 前端轮询）：跑 #14 分类 → #15 静态确认 → 按类别搜索词搜推荐物（skills 搜索，网络操作仅在此手动链路）→ 组装 pending 推荐落库
- **推荐物三家路由**：skill（按搜索词+安装量）/ hook（按类别模板生成配置草案）/ MCP（v1 降级为搜索词提示；按 tool_call 定位具体缺口的检测留待后续迭代）
- **改进清单卡片 UI**：每张卡片 = 根因 + 可展开证据链（信号原文 snippet、静态确认检查结果、搜索词、安装量，全部可追溯）+ 推荐物 + 预览/忽略；忽略后进 dismissed（#12 去重闭环保证不再回来）
- 清单哲学：会清空的改进清单，不是 feed——清单清空 = harness 改进了 = 功能成功

## Acceptance criteria

- [x] 弱提示显示项目名 + 信号条数，点击按钮触发生成
- [x] 推荐物搜索失败（网络）时降级为「仅根因诊断」卡片，不炸
- [x] 卡片证据链每一环可展开追溯
- [x] 忽略后同类推荐不再重复出现
- [x] 测试覆盖组装逻辑（搜索可注入假实现）
