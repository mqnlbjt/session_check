# Issue #15: 静态确认检查器

> Parent: 期6 改进清单（grill 重想架构：1 次纠正 + 静态确认 > 3 次纠正）

## What to build

按根因类别跑确定性验证，确认「痛点是真的 + 防护缺失」：

- 检查项来自 #14 类别配置，例如：
  - 越权改动 → 查项目有无 protected-paths 配置、有无 PreToolUse hook
  - 测试验证缺失 → 查测试框架声明（package.json scripts / pytest.ini 等）、测试命令占比
  - 工具能力缺口 → 查已装 skill/MCP 清单
- 检查结论结构化落库并附在分类结果上（「防护缺失 ✓ 确认」/「已有防护，疑似误报」）
- 推荐置信度规则：1 次纠正 + 静态确认通过 = 可推荐；静态确认发现已有防护 = 降权并说明
- API 返回每条分类结果的检查明细（供 UI 证据链展开）

## Acceptance criteria

- [x] 每个初版类别至少 2 个确定性检查项可跑
- [x] 已有防护的信号被降权且结论可解释
- [x] 检查项全部确定性（无 LLM、无网络），单项目全量检查秒级完成
- [x] 测试覆盖：有/无防护两种路径

- #14 根因分类体系（检查项绑定在类别上）
